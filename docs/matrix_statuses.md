# Спецификация статусов матрицы и обработка ошибок

Для обеспечения максимальной отказоустойчивости и прозрачности шлюз использует интеллектуальную систему классификации статусов и приоритетов в матрице мониторинга. Роутер сохраняет статусы попыток в `matrix_state` СУБД D1 асинхронно при доступной базе. Эта таблица используется для матрицы и загрузки части блокировок; текущие cooldown и fastpath также зависят от памяти isolate. Обрыв уже переданного клиенту стрима логируется отдельно и не изменяет ранее записанный статус `200`.

## Спецификация и логика работы статусов

| Статус | Цвет в матрице | Область действия | Что происходит в роутере | Как сбрасывается |
|---|---|---|---|---|
| **`200`** | Зеленый | Ячейка | Принят успешный HTTP-ответ и первый чанк тела, а не завершен весь стрим. Поздний обрыв не отменяет этот статус. | -- |
| **`404`** | Фиолетовый | Вся строка (модель) | Модель не найдена или устарела. Вся строка выводится из работы на всех ключах. | Требуется ручное обновление кэша моделей или исправление. |
| **`limit: 0`** | Сиреневый | Вся строка (модель) | Нулевая квота на бесплатном тарифе для этой модели. Роутер переходит к следующей модели в каскаде. | Сбрасывается при обновлении квот на стороне Google. |
| **`KEY_ERR`** | Красный | Вся колонка (ключ) | Невалидный ключ (ошибка 401/403). Ключ помечается как `is_valid = 0` в кэше и отключается. | Требуется замена ключа в переменных Cloudflare. |
| **`RPD`** | Бордовый | Ячейка | Исчерпан суточный лимит запросов (Requests Per Day) для связки модель-ключ. Роутер переключается на следующий ключ. | **JIT Reset:** автоматически сбрасывается в новые сутки при наступлении `00:00 UTC`. |
| **`503`** | Оранжевый | Вся строка (модель) | Модель перегружена (Service Unavailable). Вся строка блокируется для переключения на следующую модель. | Автоматически через 10 секунд. |
| **`RPM`** | Желтый | Ячейка | Превышен лимит запросов в минуту (Requests Per Minute) для ячейки. Роутер пробует следующий ключ. | Автоматически через указанный Google интервал (обычно 30--60с). |
| **`TPM`** | Желтый | Ячейка | Превышен лимит токенов в минуту (Tokens Per Minute) для ячейки. | Автоматически через 60 секунд. Требуется команда `/compact`. |
| **`TIMEOUT`** | Серый | Вся строка (модель) | `TimeoutError` до первого байта: абсолютные 60 секунд от запуска fetch, включая заголовки. Модель замораживается на 5 минут; `TIMEOUT` записывается для всех ее активных ключей, роутер переходит к следующей модели. | Автоматически через 5 минут в памяти isolate. |
| **`-`** | Темно-серый | Ячейка | Запросов по данной связке модель-ключ еще не зафиксировано. | -- |

Для ответа без тела или с немедленным EOF статус `200` может быть записан без получения байтов. Для обычного стрима первый чанк -- граница принятия ответа, а не обязательно первый полезный токен.

После первого чанка действует отдельный idle timeout 60 секунд на каждое ожидающее чтение, без общего ограничения длительности активного стрима. Если успешный ответ уже передан в SSE-пайплайн, обрыв или idle timeout записывает предупреждение, но не `TIMEOUT`, не блокирует модель и не запускает retry. Отмена запроса клиентом также не замораживает модель.

Fastpath не восстанавливается из статуса `200` в D1: `lastSuccessfulSmartModel` и `lastSuccessfulLiteModel` раздельные, а `lastSuccessfulKeyId` общий. Они обновляются при принятии ответа и существуют только в памяти текущего isolate, без глобальной синхронизации или сохранения между deploy.

## Иерархия приоритетов в матрице

Когда на одной ячейке пересекаются несколько блокировок разного уровня (например, у ключа кончился суточный лимит `RPD`, а вся модель ушла в `503` или ключ признан невалидным `KEY_ERR`), шлюз применяет строгую иерархию приоритетов для раскраски дашборда:

- **`Dead Model (404 / limit: 0)`** -- абсолютный приоритет. Если модель не поддерживается или имеет нулевой лимит, вся строка красится в фиолетовый/сиреневый цвет.
- **`Dead Key (KEY_ERR)`** -- приоритет колонки. Если ключ забанен Google, вся вертикальная колонка окрашивается в красный.
- **`Daily Limit (RPD)`** -- приоритет ячейки. Если по ключу для данной модели исчерпан суточный лимит, ячейка остается бордовой, даже если вся остальная строка покрасилась в 503.
- **`Model Overloaded (503)`** -- приоритет строки. Окрашивает всю строку в оранжевый цвет, за исключением ячеек, которые уже заблокированы по `RPD` или `KEY_ERR` (чтобы сохранить важную диагностику).
- **`Model Timeout (TIMEOUT)`** -- приоритет строки при таймауте попытки до передачи успешного ответа. Окрашивает всю строку в серый цвет на 5 минут, за исключением ячеек `RPD` и `KEY_ERR`; поздний idle timeout стрима этот статус не создает
- **`Temporary Statuses (RPM / TPM)`** -- временные локальные статусы ячеек со временем жизни до 60 секунд.
- **`Default (200 / -)`** -- базовое состояние.
