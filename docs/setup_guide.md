## Создание базы данных Cloudflare D1

База данных D1 необходима для хранения логов запросов с правильной хронологией, кэша валидации ключей и распределения трафика. Если логи вам нужны (а они просто необходимы), выполните следующие действия:

- перейдите в панель управления [Cloudflare Dashboard](https://dash.cloudflare.com/)
- в левом боковом меню перейдите по цепочке: **Storage & Databases** -> **D1 SQL Database**
- нажмите кнопку **Create database**
- в поле **Database name** укажите имя: `gemini-gateway-db`
- нажмите кнопку **Create**
- откроется страница созданной базы данных. Найдите строку **Database ID** (строка формата UUID вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`)
- скопируйте и сохраните это значение

> [!note]
> SQL-команды вручную выполнять не требуется. При деплое GitHub Actions применит исходную схему из `db/schema.sql`, затем все ещё не применённые файлы из `db/migrations/` через Wrangler D1 migrations и только после этого развернёт Worker. Wrangler записывает применённые migration-файлы в таблицу `d1_migrations`, поэтому существующие форки получат миграцию один раз при первом синке.

> [!tip]
> ***На будущее***. Если вам когда-нибудь понадобится посмотреть полный ответ логов (включая подробные JSON-дампы ошибок с лимитами или кодами ответов Google API в колонке `details`), это можно сделать двумя способами:
>
> **Способ А: Через веб-интерфейс Cloudflare Console**
> - Перейдите по адресу вашего аккаунта **Storage & Databases** -> **D1 SQL Database** -> выберите `gemini-gateway-db`.
> - Сверху откройте вкладку **Console** и выполните нужный SQL-запрос.
>
> **Способ Б: Через терминал с помощью Wrangler CLI**
> Если у вас установлен NodeJS, вы можете отправлять SQL-запросы прямо из терминала (внутри папки проекта):
> ```bash
> # Выполнить SQL-запрос удаленно
> npx wrangler d1 execute gemini-gateway-db --remote --command "SELECT timestamp, level, message, model, key_id, status, ttfb_ms, response_ms FROM logs ORDER BY timestamp DESC LIMIT 100;"
> ```
>
> Пример полезного SQL-запроса для вывода последних 100 логов:
> ```sql
> SELECT timestamp, level, message, model, key_id, status, ttfb_ms, response_ms, details
> FROM logs
> ORDER BY timestamp DESC
> LIMIT 100;
> ```

## Создание Cloudflare API токена

Для автоматического деплоя из GitHub Actions требуется API-токен с правами управления воркерами и созданной базой данных D1.

- в панели Cloudflare в левом меню в самом низу перейдите по цепочке **Manage Account** -> **Account API Tokens**
- в центральной части страницы нажмите синюю кнопку **Create API Token**
- выберите шаблон **Edit Cloudflare Workers**
- раздайте настройки доступа к базе данных D1:
  - нажмите `Add policy`
  - в появившейся форме (подписано `Search for permission groups ...`) введите `D1`
  - кликните в появившейся строке на `Read` и `Edit`
- нажмите на `Review token` и затем на `Create token`
- сохраните значение токена и **Account ID**

> [!warning]
> Токен отображается только один раз. Обязательно сохраните его (он потребуется лишь раз -- для записи в секреты GitHub Actions). Также сохраните значение **Account ID**, которое отображается в адресной строке или на главной странице аккаунта.

## Настройка секретов GitHub Actions

Создайте **Fork** этого репозитория на GitHub. Далее потребуется вставить полученные идентификаторы в настройки своего форка на GitHub:
- откройте ваш форк
- перейдите на вкладку **Settings** (расположена сверху)
- в левом меню выберите **Secrets and variables** -> **Actions**
- нажмите кнопку **New repository secret**
- добавьте по очереди следующие три секрета:
  | Key | Value |
  |---|---|
  | `CLOUDFLARE_API_TOKEN` | Cloudflare API-токен |
  | `CLOUDFLARE_ACCOUNT_ID` | Cloudflare Account ID |
  | `GATEWAY_D1_ID` | Database ID базы D1 |

## Получение ключей в Google AI Studio

Квоты бесплатного тарифа Gemini привязываются не к самому ключу, а к проекту Google Cloud. Поэтому для создания пула нужно создавать ключи в разных проектах:
- перейдите в [Google AI Studio](https://aistudio.google.com/)
- в левом верхнем углу нажмите кнопку **Get API key**
- нажмите кнопку **Create API key**
- в появившемся окне выберите вариант **Create API key in new project**
- скопируйте созданный ключ
- повторите операцию, создавая каждый следующий ключ в новом проекте
- создайте до 9 ключей

> [!note]
> Google AI Studio позволяет создать до 10 невключительно бесплатных проектов на один аккаунт. С использованием данного воркера лимиты в этих проектах скорее всего достигнуты не будут.
>
> Помните, что создание нескольких аккаунтов с целью создания нескольких проектов для расширения возможностей AI Studio будет рассмотрено как абьюз сервиса, за что ваши аккаунты могут быть заблокированы.

## Настройка переменных окружения шлюза

После выполнения первого деплоя шлюз появится в списке ваших воркеров Cloudflare. Настройте рабочие переменные:
- в панели Cloudflare в левом меню перейдите: **Workers & Pages**
- в списке воркеров выберите `gemini-edge-gateway`
- перейдите на верхнюю вкладку **Settings** -> раздел **Variables and Secrets**
- нажмите кнопку **Add**

Далее настройте следующие переменные:

| Переменная | Тип | Значение | Описание & назначение | Уточнение |
|---|---|---|---|---|
| `AUTH_SECRET*` | Secret | Пароль или список через запятую | Этим токеном шлюз авторизует запросы. Можно указать несколько (например, для разных пользователей) | Будет автоматически разбит по запятой и очищен от пробелов |
| `DASHBOARD_PASSWORD*` | Secret | Пароль или список через запятую | Если задан, браузер потребует пароль. Поддерживает несколько паролей | Будет автоматически разбит по запятой и очищен от пробелов |
| `GEMINI_KEY*` | Secret | Ключ или список через запятую | Ключи Google AI Studio. Шлюз ротирует их автоматически | Будет автоматически разбит по запятой и очищен от пробелов |

> [!important]
> **Все переменные поддерживают списки.** Если вы хотите добавить несколько ключей или паролей в одну переменную, просто перечислите их через запятую (например, `key1, key2, key3`). Шлюз сам разделит их и уберёт лишние пробелы. Это работает для `AUTH_SECRET`, `DASHBOARD_PASSWORD` и `GEMINI_KEY`. Пробелы между значениями отсекаются, так что на этот счёт можете не переживать.

> [!note]
> Регистр переменных не важен. Также под знаком `*` подразумевается, что переменная `GEMINI_KEY` может называться как `GEMINI_KEYS_123`, `gemINi-key` и т.д. и что их может быть несколько (обработка будет для всех).

> [!note]
> В именах всех переменных (`GEMINI_KEY`, `AUTH_SECRET`, `DASHBOARD_PASSWORD`) поддерживаются как подчёркивание `_`, так и дефис `-` (т.е. можно писать и `gemini-keys`, и `gemini_keys`)

Нажмите кнопку **Deploy** (или **Save and Deploy**) и готово! Переменные теперь будут применены к вашему шлюзу!

> [!tip]
> Для предотвращения географических блокировок со стороны Google и минимизации задержек рекомендуется зайти в настройки вашего воркера в панели Cloudflare (**Settings** -> **Runtime**) и включить режим **Smart**. Это автоматически перенесет выполнение кода в дата-центры США ближе к серверам Google.

## Первый запуск и проверка

Для запуска деплоя после настройки секретов выполните одно из действий:
- **Вручную (рекомендуется):** Перейдите на вкладку **Actions** вашего репозитория, выберите пайплайн `Deploy to Cloudflare Workers` и нажмите кнопку **Run workflow**.
- **Через коммит:** сделайте любое тестовое изменение (например, добавьте точку в конце любого файла) и выполните коммит в ветку `main`, а затем и пуш.

После запуска:
- дождитесь завершения пайплайна (зеленый маркер)
- откройте в браузере адрес вашего шлюза: `https://gemini-edge-gateway.your-name-in-cloudflare.workers.dev`
- если был установлен `DASHBOARD_PASSWORD`, введите его в появившемся диалоговом окне
- в блоке **KEY VALIDATION MATRIX** вы увидите статусы добавленных ключей:
  - первые 40 ключей будут проверены немедленно со статусом `VALID (200)`
  - если ключей больше 40, остальные покажут статус `UNCHECKED (?)`, и интерфейс автоматически допроверит их следующей порцией

## Подключение воркера в Zed

> [!warning]
> Как и для любой работы AI, потребуется VPN, причём работать он должен как туннель, а не как обычный прокси. Лично я пользуюсь [Hiddify](https://github.com/hiddify/hiddify-app) и для него просто ввожу доп. настройку в `settings.json`:
```json
"proxy": "http://127.0.0.1:12334",
```

> [!caution]
> Очень важно провести автодополнение вне VPN (иначе оно отключится, т.к. VPN очень сильно замедляет его действие), что возможно при помощи следующей команды в PowerShell:
> ```powershell
> [Environment]::SetEnvironmentVariable("NO_PROXY", "localhost,127.0.0.1,::1,api.zed.dev,zed.dev", "User")
> ```

Добавьте следующий фрагмент в `settings.json`:
```json
{
  "language_models": {
    "openai_compatible": {
      "Gemini Edge Gateway": {
        "api_url": "https://gemini-edge-gateway.your-name-in-cloudflare.workers.dev/v1",
        "available_models": [
          {
            "name": "gemini-smart",
            "max_tokens": 250000,
            "max_output_tokens": 65536,
            "max_completion_tokens": 65536,
            "reasoning_effort": "high",
            "capabilities": {
              "tools": true,
              "images": true,
              "parallel_tool_calls": true,
              "prompt_cache_key": false,
              "chat_completions": true,
              "interleaved_reasoning": false,
              "max_tokens_parameter": false
            }
          },
          {
            "name": "gemini-lite",
            "max_tokens": 250000,
            "max_output_tokens": 65536,
            "max_completion_tokens": 65536,
            "reasoning_effort": "high",
            "capabilities": {
              "tools": true,
              "images": true,
              "parallel_tool_calls": true,
              "prompt_cache_key": false,
              "chat_completions": true,
              "interleaved_reasoning": false,
              "max_tokens_parameter": false
            }
          }
        ]
      }
    }
  }
}
```

> Не забудьте заменить адрес `https://gemini-edge-gateway.your-name-in-cloudflare.workers.dev/v1` на адрес вашего собственного развернутого воркера.

Теперь откройте панель ассистента в Zed (`Ctrl + Alt + B` или значок чата справа). При первом обращении редактор запросит API-ключ для провайдера `Gemini Edge Gateway`. Введите значение вашего `AUTH_SECRET`, заданного в переменных окружения шлюза. Выберите модель `gemini-smart` и режим `Write` (Agent). Задайте любой вопрос или попросите отредактировать файл. Запрос успешно пройдет через шлюз, а в дашборде появится запись события со статусом 200.
